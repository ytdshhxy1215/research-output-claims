# 作者 / 发明人消歧：离线评测 v1

本报告只衡量**合成的校内人员链接任务**，不代表真实学校、论文或专利系统的准确率。待链接单位是一个 `ContributionSlot`（作者或发明人位置），标签是一个校内人员 ID 或「无校内匹配」。算法不自动认领、审批或计入统计。

## 复现

在仓库根目录用项目要求的 CPython 3.14 执行。评测只使用 Python 标准库，不需要 Django、数据库、网络、API 密钥或真实名册。

```sh
python -m apps.matching.evaluate
python -m apps.matching.evaluate --output docs/evaluation/report-local.json
python -m apps.matching.evaluate --k 1 --json
python -m pytest -p no:cacheprovider tests/test_matching_matcher.py tests/test_matching_evaluation.py tests/test_matching_recommendations.py
```

第一条命令显示论文、专利和总体结果；`--output` 写 UTF-8 完整报告（可写到任意存在的父目录），`--json` 输出同一报告到标准输出。完整报告含所有验证阈值试验、数据摘要、各组分母与计数、弃权原因、逐条错误及带分数和原因的候选证据。最后一条命令中的 Django 适配器测试使用项目的 PostgreSQL 测试设置。

## 数据版本与隔离

`synthetic-v1` 使用种子 `240711`。姓名歧义块先分组再分集，包括共享的中文姓名和显式拼音别名；隐藏身份先采样，再用独立随机流生成缺失日期、同名校外人员、错字、院系调动、噪声机构、合作/题名线索与错标的可信 ID。校外人员有同名和不同名两类。真值单独保存，匹配器只收到名册与可观察的署名记录。记录键是不透明随机值，不从人员 ID 派生；有真值的共享部门、合作名和主题并非唯一识别码。历史合作/主题仅在严格早于成果日期时可用。模拟的「可信」ID 也可能因源数据错误而指错人。

启动时校验三个集合的人员 ID、规范化姓名/别名（含观测名）、可信标识、提及 ID、成果 ID、规范化题名不交叉。这检查的是记录键和规范化文本，不是对真实成果的语义近重复检测。Challenge 为独立手写名册和案例，不经过随机生成，也不参与阈值选择；它包含同一专利中两个不同发明人的署名。

## 比较方法与阈值协议

- 两个模型用相同的原始候选召回（NFKC、大小写与标点/空白规范化后的姓名、显式别名，或完全匹配的可信 ID）。不自动转拼音、倒置姓名或编辑距离补救。姓名基线的排序与判断只用姓名/别名，两者均为 40 分；仅凭 ID 召回的候选为 0 分，不会被基线推荐。基线固定最低 35 分、差距 1 分。仅加权版使用可信 ID 评分和冲突规则；Django 不使用基线。
- `weighted-v1`：同名 +40 或别名 +35，同一命名空间的可信 ID 一致 +120；事件日有效院系一致 +30、不一致 −12；事前合作者每项 +12（最多两项）、题名中事前主题词组每项 +8（最多两项）。缺字段、无对应历史和有多个不同在任主院系均不算负分。任职区间为 `[starts_on, ends_on)`。输出可加总的分值与证据，不是概率。
- 同一命名空间的已知 ID 不一致会硬排除候选，而不是扣分。若所有候选被排除、可信 ID 指向多个候选、一个可信命中同时有冲突，或同一提及提供了同一命名空间的多个不同值，则直接弃权。缺 ID 不是冲突。其余样本无候选、低于最低分或第一、第二名分差低于最小差距时弃权；单个候选仍需达到最低分。同分按人员 ID 排序仅供复现排名，不会推荐。
- `offline-v1` 先在验证集比较 11 个最低分（40、55、60、65、70、75、80、90、100、120、150）× 5 个最小差距（1、10、15、20、30）；验证集有非零推荐且 precision ≥ 0.90 才入选，按 F1、precision、较大差距、较高分数依次决定。没有符合条件的试验就选择全弃权，绝不从测试集补选。选出的 `55 / 20` 已冻结在应用策略中，CLI 会在读入 test/challenge 之前确认验证选择一致。验证集 TP/FP/FN 为 38/4/61，precision 38/42（0.905）。0.90 是验证筛选门槛，不保证测试或生产精度。

### 指标

Precision = TP / (TP + FP)，Recall = TP / (TP + FN)，F1 为二者调和平均。对有真值的提及错人同时记 FP 和 FN，弃权只记 FN；对无校内匹配的提及错报是 FP、弃权为正确。Top-1 和 Recall@k 只以有校内真值的提及为分母，使用**剔除候选级可信冲突后、应用全局弃权与阈值前**的排名。Coverage 是所有提及中被推荐的比例；弃权率为 `1 − Coverage`。任何零分母指标记作 0。一个错误条目对应一个错误提及而非一个 FP/FN，因此错人不会重复列出。

测试集加权版推荐 112/256 条，其中 99 条正确。98 个错误提及中，85 个漏链、7 个链接错人、6 个把校外人员误连入名册。144 条弃权由无候选 50、低分 67、差距过小 20、可信冲突 7 构成。较高的 Top-1 和 F1 不意味着所有指标改善：论文精度下降，两个类型的 Recall@3 也下降（可信冲突可排除真实目标）。同名块内的样本相关，挑战集只有 12 条，且合成候选列表通常很短；不应将这些差异视为真实世界的统计结论。

挑战集加权版的完整错误摘要：`c02` 同院同名且同日历史不可用，弃权；`c08` 错误可信标识触发否决；`c09` 两项可信标识指向不同人员，弃权；`c10` 无日期不能确认院系，弃权；`c12` 校外同名人碰巧具有相同的机构线索，被误推荐。其他挑战条目涵盖调院、拼音别名、错字后的可信 ID 召回和多署名。

## 应用适配器

```python
from apps.matching.recommendations import for_researcher

recommendations = for_researcher(current_researcher)
```

返回 `list[Recommendation]`，仅包含该人员是通过加权策略的唯一第一名的署名，按分数降序后以成果/位置/署名 ID 排序。未保存或空名档案返回空列表。每项提供：

- `work`、`work_id`：`Work` ORM 对象和主键。
- `slot`、`slot_id`：`ContributionSlot` ORM 对象和主键；稳定来源键为 `slot.source_slot_id`。
- `score`、`margin`：原始整数分、第一与第二候选的分差（只有一名合格候选时为 `None`）。
- `reasons`：显示用中文字符串元组；`evidence`：含 `code`、`points`、`detail` 的证据元组；`algorithm_version`：策略版本。

适配器按成果日匹配历史主院系，院系 code 或 label 均可，如 `alpha` / `甲院`；论文用发表日，专利用已有公开/授权日期中的最早日期。现有模型没有别名、可信人员标识、已审核合作/主题历史等信号，线上适配器不伪造它们，离线表现不能视为适配器表现。为保持 Python 规范化的一致性，当前读取名册和署名候选流，适用于演示规模，未提供面向大名册的索引。函数不写入数据库、不读取或创建认领/忽略记录；视图负责认证、将调用绑定到当前账号的研究人员、以及可选的认领状态过滤。
