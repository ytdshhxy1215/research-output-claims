# 项目立项设计评审 v0.2

状态：数据源与统计口径的选型约束已澄清；方案待本人复审，未进入实现、未发仓、未验收。 | 2026-11-24

## 评审结论

把产品定位为「高校科研成果归属与统计的证据链」，而不是科研成果查询网站。最短演示路径要能回答三个问题：为什么推荐给这位老师、谁根据什么证据确认、为什么这条成果计入这个学院的这个年度。在这条线上把题目的四项要求串联起来，不先做全量抓取和图表堆叠。

## 同类产品：借鉴什么、不追什么

| 产品/实际用例 | 可核实的能力 | 本项目取舍 |
|---|---|---|
| Symplectic Elements（Stanford） | 识别 ORCID 等作者标识，向教师呈现待认领记录，也支持配置自动认领 | 借鉴认领工作台和证据展示；本项目不自动生效，专注人工归属、误认与申诉纠正 |
| Elsevier Pure | 汇总机构研究信息，供研究管理、报告和评估 | 借鉴统一目录与按口径输出；首版不覆盖完整科研管理与评估体系，做可解释下钻和冻结快照 |
| DSpace-GLAM 实际部署（NYU FDA） | 可从个人档案提交作品认领请求，再由档案管理员审核；同时承担仓储和公开展示能力 | 借鉴人员档案与成果关联、审核分工；不承载全文仓储，以双数据源增量、申诉和统计审计作为本项目演示重点 |

以上来自供应商或机构的公开材料；未做功能穷尽，不能据此断言竞品不支持申诉或版本化统计。

## 需求澄清：数据与口径

2026-11-24，学生就「是否有指定数据源、能否自选/模拟数据」和「是否必须采用真实学校口径、能否自定示例口径」向老师询问，老师回复可自行确定；学生进一步明确，公开或自生成数据均可，本作业重点验证工程能力。课程沟通截图不随代码或课程 ZIP 发布。此前关于真实专利地域、商用配额、真实源探针的阻塞项取消，不再等待第三方接入。

**P0 方案：合成数据 + 独立 HTTP 模拟源。** Docker Compose 提供 `fixture-source` 容器，分别发布论文和专利两个逻辑数据流；归集 Worker 以常规连接器、计划任务、分页和持久化水位访问它，不直接读取种子文件或写库绕过管线。预置发布批次和故障场景，演示可显式放出下一批并触发一次运行，自动调度另有验证。固定种子、生成器版本和批次清单进入仓库，给测试和答辩复用。UI、日志、报告标注模拟源和样本范围；不宣称与真实学校或商业数据同步。纯公开数据连接器以后有维护需求再接入，保留扩展接口即可，不再列厂商选型比较。

**统计口径：** 当前推荐「成果概览」与「学院考核示例」两套教学策略，以明确的署名、日期、去重和历史任职规则展示引擎差异；不是校方正式规则，无需等待学校提供正式文件。用人工可核对的小数据验证，再测试较大数据集在分页和导出下的一致性。

**评测边界：** 允许自生成带真值的数据做主评估，不把合成样本分数外推到真实学校。固定跨集合隔离的歧义组与例外场景，分论文和专利报告指标。独立手写挑战集检查生成器规律没有替代真正的消歧。

## 课程对齐：已确认 vs. 待确认

已确认：题给四项重点功能、六个一交付和明确评分权重；师生沟通确认数据源和统计口径可自定。详见[需求规格](01-需求规格.md)。尚未确认：正式课程目标、课件章节和教学方法。受托子代理仅检查指定站点的访问边界：HTTP 课程页跳转到 HTTP 登录；直接访问 HTTPS 课程和登录地址连接被重置。未提交凭据，不打开测验，不提交测验，也没有读取课件；未核验是否另有校内入口。

在看到课件前，下表为可固化的工程证据，不是已确认的课程章节映射。收到课程大纲或课件目录后，再加上章节、出处、版本及对本项目的应用或不适用理由。

| 能力方向（暂拟） | 准备提交的项目证据 |
|---|---|
| 需求分析、利益相关者、范围管理 | 用例及权限矩阵、验收用例、P0/P1 取舍、变更记录 |
| 架构设计、质量属性和权衡 | ADR、模块/数据/状态设计、失败场景、事务与审计机制 |

| 配置管理、持续交付和运维 | CI 门禁、可追溯发布附件、演示环境部署与演练证据 |
| 人机协作与软件工程实践 | 人工复审签认、Agent 建议/修订记录、独立验收证据和反事实讨论 |

## 风险及评审闸门

| 风险 | 退出条件 / 处置 |
|---|---|
| G0：模拟源流于直接导入 | 单独运行模拟 HTTP 服务；连接器从 HTTP 拉取两类资源，测试验证限流、分页故障、断点续跑、失败不推进水位和重放幂等 |
| G0：口径沿用当前人员状态导致历史失真 | 实现前用两套示例口径和手算案例固化断言，特别确认跨院合作者、历史任职和专利公开/授权的区别 |
| G1：精度好看但标签泄漏或覆盖过低 | 先冻结评测协议；建议合成验收测试集以至少 200 个已标注署名/发明人提及为初始规模，论文与专利分报；另手写挑战案例，不把模拟分数外推真实总体。设置阈值先于最终测试；上线建议先谈精度/覆盖取舍，不预填成绩 |
| G1：权限和竞态只在演示中“看起来对” | PostgreSQL 上验证并发审批约束，跑三角色端到端；必须有负例（越权、同时批准、原审核人复核和重复请求） |
| G2：工程建设占用主要功能时间 | 先跑通垂直切片再加特性；CI 与 Compose 早搭骨架，拒绝重架构；离线可复现、模拟同步可证、最终作业包与镜像出自同一版本 |
| G2：公开仓库泄露课程或人员数据 | 本地先起草；用户确认许可证、数据边界及仓库发布范围，检查当前树、历史、日志和 Release 附件，才创建或公开 GitHub 仓库 |

### 建议的实施里程碑（此轮不执行）

1. **固化验收：** 定义模拟源契约、发布批次、评测设计与手算示例；明确课程知识映射待补项。若未核准公开，仍可用合成数据进行本地开发。
2. **交付最短纵切：** 论文增量 → 匹配 → 教师认领 → 院系审核 → 一套口径；同时交付 Compose、基础 CI 和两批 HTTP 同步集成测试。
3. **补齐风险能力：** 专利增量、申诉与独立复核、两套口径和历史快照；消歧试验与评估、权限并发、失败恢复、E2E。
4. **发布与答辩：** README、体感打磨、可复现部署与 Release、六个一打包、课程追踪及真实的 Agent 协作复盘、≤300 字摘要。
