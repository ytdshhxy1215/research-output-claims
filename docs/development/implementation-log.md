# 首批实现与 Agent 协作记录 · 2026-11-25

本记录是过程证据，不替代课程最终个人复盘。P0 目标是五个容器从空卷启动后，经真实 HTTP 把合成论文/专利拉入 PostgreSQL，再完成认领与统计。不引入 Redis，也不接真实学校数据。

| 任务 | 子代理交付 | 验收方式 |
|---|---|---|
| 容器 | 固定基础镜像、锁定安装、Compose、健康检查、数据库卷、操作文档 | Docker 构建、空卷迁移、应用非 root、HTTP 就绪、静态资源、演示账户 |
| CI / Release | GitHub Actions、Compose 冒烟、HTTP 表单验证、演示 ZIP 和校验文件 | `actionlint`、本地实际冒烟与 ZIP 校验；GitHub 执行状态单独记录 |
| 归集 | 模拟源、稳定署名、窗口与持久队列、人工重放 | 两批真实 HTTP、PostgreSQL 集成故障注入、锁/租约断言、重复终态核对 |
| 消歧 | 姓名基线、多证据推荐与弃权、冻结数据和评估命令 | 256 条冻结测试提及、12 条挑战案例、独立阈值验证、给本人显示证据 |
| 认领 | 角色化服务、撤销与申诉、并发单一有效归属、审计 | PostgreSQL 并发和权限测试；实际带 Cookie / CSRF 的 HTTP 业务链 |
| 统计 | 两套口径、历史归属、过滤与 CSV、不可变快照 | BIZ-04/05/06 黄金用例、越权和快照并发测试 |

主 Agent 实现账户环境、项目骨架和同步运行页面；拆分文件写入范围、固定 API 契约、接纳成果后在同一版本复跑检查。网络中断后先检查文件、镜像和锁定依赖，再重启六个工作项。集成中发现推荐忽略的模型被两边同时实现，保留认领模块已有的单一实现；测试环境没有静态资源清单时页面测试误红，项目增设测试专用静态存储，容器保留严格清单并由 HTTP 冒烟验证真实静态资源。

项目负责人已确认数据源与统计口径可自定、希望用 Docker；技术取舍与具体实现记录为 Agent 的工作，不冒记为学生已做的判断。

当前边界：阶段实现仅支持合成固定窗口和人工进批；在线推荐特征只使用现有名册与来源提供的姓名/历史院系，离线评测里的额外证据不等于线上已接入。HTTP 冒烟不是 Playwright 浏览器回归；没有真实数据源、生产托管或最终课程提交包。
