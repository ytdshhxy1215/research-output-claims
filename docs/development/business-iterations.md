# 业务迭代清单

本轮以教学演示和角色可执行性为准，不以页面数量为目标。

| 调整 | 原因 | 可观察结果 |
|---|---|---|
| 教师申请按阶段查询 | 状态混排，不容易发现驳回后可以申诉 | 可从「可申诉」筛到初审驳回；打开原申请发起申诉，不重复创建案件 |
| 审核默认只看可决定的待办 | 历史、仅可转派、已被隔离的申请不应计入待办 | 院系只看本院可初审；校级只看可补位初审、可独立复核；可切换授权历史 |
| 保留原有详情、审计和权限 | 列表优化不能决定业务权限 | 两个列表独立分页，服务端仍按对象校验；竞争申请不暴露给本人 |
| 暂缓批量审批、自动认领、复杂流程配置 | 高风险或会掩盖逐案证据；课程核心不依赖这些能力 | 不增加相关入口或权限；不因引入新视图改写历史记录 |

**下一轮优先候选**：给同步运维提供受控重放入口和原因记录，替代演示中手工找运行 ID；随后补认领超时提醒（仅提醒，不自动审批）与审计筛选。真正发布/上线前由负责人确认开源许可证、备份恢复和主机权限。

本轮规则、状态和验收分别见 [认领工作流](../architecture/claims.md)、[独立队列用例](../../tests/test_acceptance_queue.py) 与 [交付路径](../operations/ci.md)。
